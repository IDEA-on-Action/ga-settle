## 1. 요약 (Executive Summary)

**한 줄 정의:**
매월 이미지 포스터로 오는 보험사 시책안을 OCR로 읽어 시책룰 초안을 만들고, 정산 담당자가 좌(원본)/우(추출 룰) 대조로 확정하며, 원본 이미지가 금감원 감사 지급 근거로 보관되는 기능.

**배경:**
ga-settle은 30개 원수사 엑셀을 AI 매핑으로 표준화해 정산·대사·마감까지 자동화한다. 그러나 "얼마를 지급하는가"를 정하는 **시책안**은 매월 보험사 제작 **이미지 포스터**로 도착해, 담당자가 눈으로 읽어 시책룰을 수기 입력하고 있다. 월중 수시 개정(2026-03 생보 4회)까지 겹쳐 입력 부담·오입력·근거 추적 공백이 크다.

**목표:**
시책안 이미지 → OCR 추출 → HITL 좌우 대조 확정 → 시책룰 등록 + 원본 근거 보관의 반자동 파이프라인. 정산 핵심값은 상용 OCR 기준 사실상 전량 정확 인식하고, 잔여 오류는 3중 검증으로 정산 오류 전이를 차단한다.

## 2. 문제 정의

### 2.1 현재 상태 (As-Is)
- 시책안이 매월 pptx 포스터(슬라이드 전체가 이미지, 텍스트 추출 불가)로 도착 → 시책룰 수기 입력.
- 월중 수시 개정(2026-03 생보 시책안 4회: 3/5·3/16·3/17·3/18) → 버전·적용시점 추적 공백.
- 금감원 감사 시 특정 지급 건의 근거 시책안을 되짚을 체계 부재(엑셀 수작업 운영, 월 1,475건/2.4억).

### 2.2 목표 상태 (To-Be)
- 이미지 업로드 → OCR이 지급률·배수·적용기간·대상(상품·채널·조건) 자동 추출·구조화.
- 좌(원본 이미지)/우(추출 룰) 대조 화면, 신뢰도 낮은 값 색 표시로 확인 유도.
- 담당자 확정 후에만 시책룰 등록, 금액은 결정적 코드가 계산(AI는 후보/근거만).
- 확정 룰 ↔ 원본 이미지 + 추출·수정 이력 연결 → 지급 건 클릭 시 원본까지 역추적.

### 2.3 시급성
- 위시켓 156459 수주활동(제안 단계). 고객 Q2가 프로세스·화면을 직접 질의 → 제안 데모 반영으로 설득력 확보.

## 6. 제약 조건

### 6.1 일정
- 데모 PoC: 즉시(본 작업). 정식 개발: 계약 후 마일스톤 협의.

### 6.2 기술 스택 (CLAUDE.md 고정, 변경 금지)
- 프론트: React 18 + Vite + TS(strict) + Tailwind 4 + shadcn/ui + TanStack Query (정식 SPA는 B-006). 데모는 apps/api demo.ts 자체완결 HTML.
- 백엔드: CF Workers + Hono + Zod. 인프라: D1(Drizzle) + R2 + Queue.
- 기존 의존: incentive_rules 테이블(존재), F-010 시책룰 CRUD, F-012 시뮬레이션, R2 uploads 버킷.

### 6.3 인력/예산
- 개발 견적 3,000만원에 OCR·AI 비용 포함. 운영: 오픈소스 0원 / 상용 월 1만원 내외.

### 6.4 컴플라이언스
- 도메인 불변식: AI 출력 금액 직접 계산 경로 금지, PII 마스킹 표본만 AI 전달, 모든 쓰기 audit 동반, GPU 불필요.
- 하반기 홈페이지 취약점 점검 일정 이후 리뉴얼 병행 가능(Q6).
