## Part 1: 왜 (목적/문제)

**As-Is**
- 시책안(보험사 → GA 지급 규칙)이 매월 **이미지 포스터**(pptx 슬라이드 전체가 보험사 제작 포스터)로 도착.
- 담당자가 포스터를 눈으로 읽어 시책룰(지급률·배수·적용기간·대상)을 **수기 입력**.
- 월중 수시 개정(2026년 3월 생보 시책안만 4회 개정: 3/5, 3/16, 3/17, 3/18).
- 금감원 감사 대비, 특정 지급 건이 "어느 시책안의 어느 조건"에서 나왔는지 **지급 근거 원본**을 제시할 수 있어야 함.

**To-Be** (서민원 답변 Q2)
- 시책안 이미지 업로드 → OCR이 지급률·배수·적용기간·대상(상품·채널·조건) 자동 추출.
- 화면: **좌(원본 시책안 이미지) / 우(추출된 룰 항목)** 나란히 대조, 신뢰도 낮은 값은 색으로 표시.
- 담당자 확인·보정 후 시책룰로 확정. 실제 금액은 검증된 결정적 코드가 계산(AI는 후보/근거만).
- 확정 룰에 원본 이미지 + 추출·수정 이력 보관·연결 → 감사 시 원본까지 역추적·소명.

**시급성**: 위시켓 156459 수주활동(제안 단계). 고객 Q2가 "프로세스와 화면 구성"을 직접 질의 → 제안 데모에 반영해 설득력 강화 필요.

## Part 3: 무엇을 (범위)

**핵심 한 문장**: 시책안 이미지를 올리면 OCR이 시책룰 초안을 만들고, 담당자가 좌우 대조로 확정하며, 원본이 지급 근거로 보관된다.

**결정 사항 (인터뷰)**
- OCR 엔진: **하이브리드** - 오픈소스(EasyOCR 90%) 1차 + 저신뢰 항목만 상용 API(Upstage/CLOVA 98-99%) 폴백/담당자 확인. 자체서버 0원 기본, 핵심값 정확도 보강. (문의답변 비용 포지셔닝과 일치)
- 자동화 깊이: **추출 + 룰 구조화** - OCR이 지급률·배수·적용기간·대상을 시책룰 필드로 자동 구조화 + 좌우 대조·신뢰도 표시.
- 반영 시점: **제안 데모에 지금 반영** - `ata.minu.best` 데모에 경량 PoC로 즉시 반영(수주 설득).

**Out-of-scope (이번 데모 PoC)**
- 실 OCR 엔진 서버 상시 구동(EasyOCR/상용 API 실연동)은 계약 후 정식 개발. 데모는 실 포스터 데이터 기반 시뮬레이션 + OCR-ready seam.
- 전 보험사 전 시책 유형 완전 구조화(손보 318열 비정형 전량)는 후속. 데모는 검증된 대표 포스터 2종(KB손보 주차시상 표밀집형, 한화손보 여성시대 장식폰트형) 범위.

**외부 연동**: OCR 엔진(오픈소스 자체호스팅 / 상용 API) - 계약 후 확정. 데모 단계 무연동.

## Part 4: 성공 기준

- 정산 핵심값(지급률·금액·상품명) 상용 엔진 기준 사실상 전량 정확 인식(실측 98-99%).
- 3중 검증으로 잔여 오류가 정산 오류로 이어지지 않음: ①신뢰도 표시 ②담당자 확정 ③원본 근거 보관.
- 데모 관점: 좌우 대조·신뢰도 색·확정·원본 역추적 UX가 고객 화면에서 재현되어 Q2 답변을 시연.

## Part 5: 제약과 리소스

- 스택 고정(CLAUDE.md): CF Workers + Hono + Zod / D1(Drizzle) / R2(이미지 불변 보관) / apps/web React. 변경 금지.
- 도메인 불변식: AI 출력은 금액 계산 직접 경로 금지(후보/근거만), PII 마스킹 후 표본만 AI 전달, 모든 쓰기 audit 동반.
- 운영 비용: 자체서버(오픈소스) 0원 / 상용 API 월 1만원 내외 - 정산 규모(2.4억) 대비 무시.
- 인프라: GPU 불필요(학습=매핑·규칙 저장·재사용, 딥러닝 재훈련 아님).
- 예산: 개발 견적 3,000만원에 OCR·AI 비용 포함.
