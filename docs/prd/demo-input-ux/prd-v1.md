# PRD - 데모 입력 진입장벽 제거

## 1. 배경 / 문제

고객(에이티에셋) 데모 사용 피드백: **화면을 진행하려면 사전 지식이 필요한 지점이 많아 막힌다.**

코드 감사(2026-07-10)로 확인한 공통 원인: **불투명한 ID를 화면 간에 손으로 옮겨 입력**해야 하고, 조회·선택 수단이 없다. 대표 사례 - 업로드 화면은 `원수사 ID`(insurerId)를 직접 입력해야 파일을 올릴 수 있는데, 그 ID는 어디에도 표시되지 않는다.

### 감사로 식별한 진입장벽

| 입력 | 화면 | 현재 | 원인 |
|---|---|---|---|
| 원수사 ID (insurerId) | 업로드, 매핑관리 | 슬러그 손입력 | 목록 API는 있으나 UI 미연결(주석도 낡음) |
| uploadId (UUID) | AI매핑검토, 매핑관리, 대시보드 | 업로드 화면서 복사 | 업로드 목록 API 부재 |
| run id (UUID) | 대사, 내역서, 대시보드 | Run 화면서 복사 | Run 목록 API 부재 |
| 승인자·확정자 이름 | 보정, 마감, 가족확정 | 자유 텍스트 | 로그인 사용자 미활용(감사 무결성 약화) |

## 2. 목표 / 성공 지표

- **G1**: 데모 핵심 흐름(업로드 → 매핑 → 정산 → 대사 → 내역서)을 **UUID 손입력 없이** 완주할 수 있다.
- **G2**: 사용자가 값을 "알아야" 진행 가능한 필드를 선택기(드롭다운/목록)로 대체한다.
- **G3**: 승인자·확정자는 로그인 사용자로 자동 기록되어 감사 무결성이 강화된다.
- **지표**: 위 5개 화면에서 사용자가 손으로 타이핑해야 하는 opaque ID 입력 개수 = 0.

## 3. 사용자 / 범위

- **주 사용자**: 정산 담당자(admin/manager) - 데모 평가자 포함.
- **In scope**: 아래 F-035~F-038. 프론트 선택기 + 필요한 목록 조회 API.
- **Out of scope**: 계약ID/설계사코드 선택기(보정·가족감지 상세 조회) - 별도 후속(B). 신규 원수사 등록 UI(현행 API로 가능, 이번 미포함). 권한별 필터 고도화.

## 4. 요구사항 (F-item 단위)

### F-035 · 원수사 선택 드롭다운 (프론트, REQ-051)
- 업로드/매핑관리의 `insurerId` 손입력을 `GET /api/insurers` 기반 드롭다운(이름 표시, id 전송)으로 대체.
- 낡은 주석("GET /api/insurers 부재") 제거.
- **AC**: 업로드 화면에서 원수사를 목록에서 선택해 업로드할 수 있다. id를 몰라도 된다.

### F-036 · 업로드 목록 API + 최근 업로드 선택기 (REQ-052)
- `GET /api/uploads` 신규: 최근 업로드 목록(id, 원수사, 정산월, 상태, 시각) 반환.
- AI매핑검토/매핑관리/대시보드의 `uploadId` 입력을 선택기로 대체(최근순, 원수사·월·상태 라벨).
- **AC**: 업로드 화면에서 UUID를 복사하지 않고도 매핑 화면에서 대상 업로드를 고를 수 있다.

### F-037 · 정산 Run 목록 API + 월/Run 선택기 (REQ-053)
- `GET /api/runs` 신규: Run 목록(id, 정산월, 상태, 시각) 반환.
- 대사/내역서/대시보드의 `run id` 입력을 월·상태 라벨 선택기로 대체.
- **AC**: run UUID를 복사하지 않고도 대사·내역서 화면에서 대상 Run을 고를 수 있다.

### F-038 · 승인자·확정자 로그인 사용자 자동 반영 (REQ-054)
- 보정(이중 승인자)/마감(closedBy)/가족확정(확정자)의 자유 입력을 **로그인 사용자**로 자동 채움(표시는 하되 수정 최소화).
- 서버가 인증 컨텍스트의 사용자 신원을 감사 필드로 기록.
- **AC**: 보정/마감/확정 시 별도 이름 입력 없이 로그인 사용자가 감사 로그에 남는다.

## 5. 기술 결정

- **원수사 드롭다운**: 프론트 전용. TanStack Query로 `GET /api/insurers` 캐시. 신규 shadcn Select 또는 기존 select.tsx 재사용.
- **목록 API 2종**: Hono 라우트 추가(uploads.ts, runs.ts). 페이지네이션은 최근 N개(기본 50) 단순 반환으로 시작. 민감정보 미포함(집계·상태만).
- **승인자 자동화**: 프론트는 auth 컨텍스트 email/id 사용, 서버는 `authUser`로 재확인(신뢰 경계는 서버). 기존 자유입력 필드는 읽기전용/자동채움으로 전환.
- 불변 원칙 준수: 목록 API는 조회 전용, 마감/역추적/감사 규칙 무변경.

## 6. 리스크

- 목록 API가 민감정보(금액/인적)를 노출하지 않도록 필드 화이트리스트 필수(도메인 불변식 5).
- 승인자 자동화가 기존 이중 승인(사람 2인) 의미를 흐리지 않도록, "요청자=로그인 사용자"와 "승인자"는 역할 구분 유지(마감·보정의 이중 통제 정책 확인).
- 대량 업로드/Run 시 목록 길이 - 최근 N개 제한으로 완화.

## 7. Out-of-scope / 후속(Backlog)

- 계약ID/설계사코드 선택기(보정·가족감지) → 조회 팝업 필요, 후속.
- 신규 원수사 등록 UI.
- 목록 필터/검색/페이지네이션 고도화.
